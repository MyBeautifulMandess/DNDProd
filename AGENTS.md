# Правила работы агентов в этом репозитории

## Главное

1. **Игровые данные — только из `data/catalogs/`** или по ссылке на https://dnd.su. Никаких выдуманных чисел, названий, уровней умений.
2. **Официальные правила D&D 5e (2014)** — приоритет. Homebrew не добавлять без явной команды.
3. Язык UI и документации — русский; идентификаторы кода — английский snake_case.
4. Терминология — по `docs/10-glossary.md`.
5. **Кроссплатформенность Windows → Android и macOS обязательна**: стек Flutter, платформенный код только в `platform/` за интерфейсами, без WinAPI и hover-only UI. См. `docs/01-architecture.md`, раздел «Правила переносимости».

## Обязательные файлы

- Входная точка: `docs/00-index.md` (оглавление и правила).
- Архитектура: `docs/01-architecture.md`.
- План: `docs/07-roadmap.md` — обновлять после каждой задачи (отмечать `- [x]`, новое — добавлять).

## Пересборка данных

Каталоги собираются скриптом:

```bash
python tools/build_catalogs.py            # всё
python tools/build_catalogs.py spells     # один раздел: spells | bestiary | items | race
```

Не править JSON вручную — править скрипт и пересобирать.

## Git

- Коммиты маленькие, атомарные. Префиксы: `data:`, `docs:`, `core:`, `player:`, `master:`, `lobby:`, `ui:`.
- Не коммитить секреты, ключи API, большие бинарники (ассеты пользователь добавляет сам).

## Делегирование токенозатратных задач (RouterAI)

По глобальным правилам (`~/.agents/AGENTS.md`): основной агент — оркестратор
и UI-дизайнер, тяжёлые задачи делегирует дешёвым моделям. Обёртка в репозитории —
`tools/routerai_delegate.py` (вызывает `~/.routerai/routerai_delegate.py`),
ключ — `~/.routerai/key`. Дополнение к глобальным правилам: делегированный код
подчиняется правилам этого файла — игровые данные только из `data/catalogs/`
или с https://dnd.su.

## Если что-то неясно

- Сначала смотри `docs/`. Если ответа нет — принимай решение по официальным правилам dnd.su и фиксируй допущение в `docs/07-roadmap.md` (раздел «Принятые допущения»).
