# D&D Помощник (DNDProd)

Flutter-приложение для мастеров и игроков D&D 5e (2014). Две роли на входе — **Игрок** и **Мастер**. Игровые данные берутся только из официальных каталогов [dnd.su](https://dnd.su); справочники работают офлайн, а лобби поднимается прямо на устройстве мастера в локальной сети.

Поддерживаемые платформы: **Windows**, **Android**, **macOS** (таргет подготовлен; сборка `.app` выполняется на Mac с Xcode).

[Скачать последний релиз](https://github.com/MyBeautifulMandess/DNDProd/releases/latest) · [Документация](docs/00-index.md)

## Установка готовыми пакетами

Готовые пакеты лежат в [последнем релизе](https://github.com/MyBeautifulMandess/DNDProd/releases/latest):

| Платформа | Файл | Как ставить |
|---|---|---|
| **Windows 10/11 (x64)** | `DNDProd-setup-win-x64.exe` | Запустите установщик, дальше — по шагам мастера. Приложение появится в меню «Пуск» как «D&D Помощник». Удаление — через ярлык «Удалить D&D Помощник» в меню «Пуск». |
| **macOS** | `DNDProd-macOS.dmg` (если собран) | Откройте образ, перетащите «D&D Помощник» в «Программы». Пакет без подписи Developer ID: при первом запуске сделайте правый клик по приложению → «Открыть» → «Открыть». |
| **Android 8+** | `app-release.apk` | Скачайте на устройство и откройте файл. Разрешите установку из неизвестных источников. APK подписан debug-ключом, это тестовая сборка. |

Установщик Windows собран через встроенный в Windows IExpress и не требует прав администратора: он распаковывает приложение в `%LOCALAPPDATA%\DNDProd` и создаёт ярлыки в меню «Пуск». При установке/удалении данные персонажей и приключений в «Документах» не затрагиваются.

DMG для macOS в этом репозитории не хранится — `.app` можно собрать только на Mac с Xcode. На macOS запустите `./installer/macos/build_dmg.sh`, и файл `installer/macos/DNDProd-macOS.dmg` будет готов к распространению. Для публикации вне своего компьютера пакет нужно подписать Developer ID и пройти notarization; скрипт накладывает лишь ad-hoc подпись.

Подробности сборки установщиков — в разделе «Сборка релиза» ниже.

## Что умеет

- **Игрок**
  - Создание персонажа 1–20 уровня: раса и подвид, класс, характеристики, предыстория, снаряжение, заклинания, аватар.
  - Сохранение нескольких персонажей, дублирование, удаление, экспорт/импорт JSON, прокачка уровня и экран просмотра.
  - Быстрый лист в сессии: хиты, характеристики, спасброски, 18 навыков, известные заклинания, снаряжение; броски идут в чат.
  - Справочники: заклинания, бестиарий, предметы, черты, предыстории — поиск, фильтры, полные тексты, ссылка на источник.
- **Мастер**
  - Приключения: карты, лор и ПМ, подготовка тумана и расстановка монстров до игры, запуск комнаты из карты.
  - Комната: переключение карт на лету, пешки с хитами, туман, кисть, линейка, чат, броски (включая скрытые), показ картинок игрокам.
  - Архив подключившихся персонажей и NPC, быстрая подгрузка монстров/предметов/заклинаний из справочника одним действием.
  - Возврат правок сессии обратно в приключение.
- **Общее**
  - Сервер лобби на устройстве мастера (`shelf_web_socket`), клиенты на `web_socket_channel`, адрес `IP:7777` и QR-код.
  - Единая кодовая база: платформо-зависимый код изолирован в `platform/` за интерфейсами.

## Требования

- Flutter **3.44.1** (Dart 3.12.1), `flutter doctor` без ошибок.
- Для Windows: Visual Studio 2022 с workload «Desktop development with C++».
- Для Android: Android SDK 36 + JDK 17; эмулятор не обязателен.
- Для macOS: Xcode (только на машине с macOS).

## Быстрый старт

```bash
git clone https://github.com/MyBeautifulMandess/DNDProd.git
cd DNDProd
flutter pub get
flutter analyze
flutter test
flutter run -d windows
```

Каталоги `data/catalogs/`, готовые ассеты и `pubspec.lock` уже лежат в репозитории — после клона ничего дособирать не нужно.

## Сборка релиза

```bash
flutter build windows --debug       # build/windows/x64/runner/Debug/dnd_prod.exe
flutter build apk --release         # build/app/outputs/flutter-apk/app-release.apk
flutter build macos --release       # только на macOS с Xcode
```

APK в релизе подписан debug-ключом: его можно ставить на устройство для тестирования, но для публикации в магазине нужен собственный keystore. Настройки сборки Android находятся в `android/app/build.gradle.kts` и `android/gradle.properties`.

### Сборка установщиков

**Windows.** Нужен встроенный в Windows `iexpress.exe` (есть в любом Windows без дополнительных программ):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File installer/windows/build_installer.ps1
```

Скрипт сам соберёт Flutter Windows Release, упакует его и создаст `installer/windows/DNDProd-setup-win-x64.exe`. Проверено: установщик распаковывается, ставит приложение в `%LOCALAPPDATA%\DNDProd`, создаёт ярлыки в «Пуск», приложение запускается, удаление работает. Готовый `.exe` — актив релиза, в репозиторий не коммитится.

**macOS.** На машине с macOS и Xcode:

```bash
chmod +x installer/macos/build_dmg.sh
./installer/macos/build_dmg.sh
```

На выходе `installer/macos/DNDProd-macOS.dmg`. Скрипт собирает release, переименовывает `.app` в «D&D Помощник», накладывает ad-hoc подпись и упаковывает DMG через `hdiutil`. Файл `.dmg` в репозиторий не коммитится — его нужно прикрепить к релизу отдельно.

**Android.** `flutter build apk --release`, затем прикрепите `build/app/outputs/flutter-apk/app-release.apk` к релизу.

## Игра в локальной сети

1. Мастер открывает приключение и запускает комнату; приложение показывает адрес вида `192.168.1.5:7777` и QR-код.
2. Игроки подключаются к той же Wi-Fi сети, выбирают роль «Игрок» и вводят адрес мастера (сканер камеры пока не реализован).
3. Мастер видит всех игроков и пешки, игрок — только свою. Права проверяются на сервере.

Для LAN разрешён cleartext-трафик: лобби работает по `ws://`, карта и картинки раздаются мастером по `http://`. Для выхода в интернет (фаза 6) планируются HTTPS/WSS, пароль комнаты и шифрование. Если устройство не видит комнату, проверьте ту же сеть и фаервол на порту 7777.

## Данные и пересборка каталогов

Источник истины — `data/catalogs/` (собраны с dnd.su). JSON вручную не правят: меняют парсеры в `tools/build_catalogs.py` и пересобирают:

```bash
python tools/build_catalogs.py              # все разделы
python tools/build_catalogs.py spells       # один раздел
python tools/build_catalogs.py race_detail class_equipment backgrounds
```

Бестиарий хранится как лёгкий индекс `_bestiary_index.json` и 32 шарда с полными карточками: список и фильтры читают только индекс, карточка подгружает свой шард по требованию.

## Структура

| Путь | Назначение |
|---|---|
| `core/` | Чистые правила D&D, модели (`Character`, `Room`, `Adventure`) и формулы бросков — без UI и платформы |
| `data/catalog_loader.dart` | Загрузка каталогов из assets, поиск, кэш и предзагрузка |
| `platform/` | Файлы, WebSocket-сервер/клиент, сетевые адреса — за интерфейсами |
| `player/`, `master/`, `lobby/`, `shared/` | UI и контроллеры ролей, лобби и общие виджеты (поле, чат, справочники) |
| `test/` | Юнит- и виджет-тесты |
| `test_driver/` | Сценарии на устройстве через `flutter_driver` |
| `docs/` | Архитектура, правила данных, план работ и журнал прогресса для агентов |

## Тесты и сценарии на Android

```bash
flutter test
flutter emulators --launch dnd_prod_avd
flutter drive --target=test_driver/app.dart \
  --driver=test_driver/scenarios_test.dart -d emulator-5554
```

Сценарии проверяют нижние табы игрока и запуск комнаты мастером на реальном эмуляторе. Виджет-тесты адаптивной навигации отдельно проверяют узкий и широкий режимы.

## Ограничения

- Интернет-режим, пароли комнат и шифрование — не реализованы (фаза 6).
- Мультикласс и выбор покровителя колдуна в билдере пока не сделаны.
- macOS `.app` собирается только на Mac; на Windows проверены генерация таргета, анализатор и тесты.
- APK в релизе подписан debug-ключом; cleartext разрешён только для локальной сети.
