# 01 — Архитектура приложения

Цель: **десктопное приложение для Windows**, спроектированное так, чтобы его можно было **почти без переписывания перенести на Android и macOS**. Две роли на входе — **Игрок** и **Мастер**. На старте — локальная сеть, далее — интернет через сервер мастера.

## 1. Главный принцип: кроссплатформенность из коробки

- **Единая кодовая база** для Windows, Android и macOS. Платформо-специфичный код (файлы, сеть, SQLite) изолируется за интерфейсами и занимает минимум строк.
- **Роль (Игрок/Мастер)** определяется на входе — это одно приложение, а не два.
- **Офлайн-ферст**: справочники работают без сети; `data/catalogs/` вшивается в приложение.
- **Лобби — сервер на устройстве мастера**; игроки — клиенты. На Android мастер тоже может поднять сервер (Wi-Fi).
- **UI адаптивен**: экраны проектируются так, чтобы работать и с мышью/клавиатурой, и с тачем (крупные hit-area, нижние панели, свайпы).

## 2. Технологический стек (выбран)

Чтобы гарантировать лёгкий перенос на Android и macOS, стек фиксируется так:

- **Flutter (Dart)** — один UI-код компилируется в Windows/macOS-десктоп и Android APK. Canvas для игрового поля, богатые виджеты, отличная производительность.
- **Слой данных**: `drift` (SQLite) для справочников и пользовательских данных + JSON для экспорта персонажей.
- **Сеть**: `web_socket_channel` (WebSocket), локальный сервер на Dart (`shelf_web_socket`) — одинаково работает на Windows и Android.
- **Игровое поле**: CustomPainter (Canvas) с сеткой, фоном и туманом; панорама/зум — `InteractiveViewer`. Общий виджет — `lib/shared/field/battle_field.dart`, там же источник фона (`asset:` или HTTP-URL карты мастера); ассеты из `assets/2d/` и `assets/maps/` (см. `08-assets.md`).
- **Платформо-зависимости**: только через плагины (path_provider, connectivity_plus, qr_flutter). Никакого прямого вызова WinAPI — только абстракции.

Если агент меняет стек — обновляет этот файл и `07-roadmap.md`.

## 3. Правила переносимости (обязательны для агента)

1. **Никакого кода, завязанного только на Windows**: запрещены прямые вызовы Win32, реестра, путей `C:\`. Пути — через `path_provider`; конфиг — через `shared_preferences` или JSON.
2. **UI без hover-зависимостей**: всё, что можно кликнуть мышью, должно быть доступно пальцем (минимум 44×44 px).
3. **Адаптивная вёрстка**: используем `LayoutBuilder`/`MediaQuery`, а не фиксированные размеры окна. Нижняя навигация на телефоне, боковая/верхняя на десктопе.
4. **Изоляция платформы**: платформо-специфичная логика (сервер, фоновые задачи, файлы) — в `platform/` за интерфейсами, с двумя реализациями максимум (desktop, mobile).
5. **Нет глобального состояния в UI**: состояние — в контроллерах/BLoC, чтобы легко менять навигацию под форм-фактор.
6. **Ресурсы**: все ассеты в `assets/`, пути через `pubspec.yaml` — одинаково упаковываются на всех платформах.

## 4. Модули

```
app/
├── core/               # чистая логика, без UI и платформы
│   ├── rules/          # формулы D&D: модификаторы, КЗ, хиты, CR, броски
│   ├── models/         # Character, Monster, Spell, Item, Adventure, Map, Token
│   └── engine/         # прокачка персонажа, валидация, расчёт статов
├── data/
│   ├── catalogs/       # снапшот data/catalogs/*.json, зашитый в приложение
│   └── local/          # SQLite (drift) + пользовательские JSON
├── platform/           # платформо-зависимые абстракции
│   ├── files/          # пути, экспорт/импорт
│   ├── network/        # сервер/клиент WebSocket
│   └── device/         # QR, вибро, keep-alive
├── player/             # UI и логика роли «Игрок»
│   ├── builder/        # создание и прокачка персонажа
│   ├── sheet/          # лист персонажа в игре
│   └── library/        # справочники: заклинания, бестиарий, предметы
├── master/             # UI и логика роли «Мастер»
│   ├── adventures/     # приключения, карты, заготовки
│   └── room/           # запущенная комната: поле, туман, трекер
├── lobby/              # сеть: сервер (мастер) и клиент (игрок)
│   ├── protocol/       # сообщения, версия протокола
│   ├── server/         # WebSocket-сервер на устройстве мастера
│   └── client/         # подключение к комнате
├── shared/             # общий UI: кубики, чат, линейка, рисование
└── assets/             # 2D-ассеты, карты (из assets/)
```

## 5. Ключевые сущности

- **Character** — персонаж игрока: раса, класс, уровень, подкласс, характеристики, навыки, хиты, заклинания, инвентарь, предыстория, аватар. Локально, экспорт в JSON.
- **Adventure** — приключение мастера: карты, токены врагов с трекерами, лор, ПМ, настройки тумана.
- **Room** — запущенная сессия: активная карта, токены, туман, чат, броски. Живёт, пока мастер не закроет комнату.
- **Token** — пешка на карте: персонаж игрока или монстр; позиция, размер, хиты.
- **CatalogEntry** — запись справочника (заклинание/монстр/предмет), ссылка на `data/catalogs/` + опционально dnd.su.

## 6. Потоки (high-level)

**Создание персонажа** → `player/builder`: раса → класс → характеристики → предыстория → заклинания/снаряжение → аватар → сохранение.

**Запуск сессии** → мастер открывает приключение → запускает комнату → получает адрес/QR → игроки подключаются со своих устройств (в т.ч. Android).

**Во время игры** → синхронизация карты, перемещение своей пешки (игрок), полный контроль (мастер), скрытые броски, чат, хиты.

## 7. Конфигурация и версии

- Версия протокола лобби — отдельное поле, чтобы избежать рассинхрона.
- Версия данных справочников = дата снапшота dnd.su. Пересбор через `tools/build_catalogs.py`.
- Никаких секретов в репозитории. Конфиг — `config/app.json` с дефолтами.

## 8. Что здесь зафиксировано навсегда

- Две роли на входе: Игрок / Мастер.
- Справочники офлайн из `data/catalogs/`.
- Сервер лобби на устройстве мастера.
- Официальные правила 5e (dnd.su) как единственный источник.
- **Кроссплатформенность Windows → Android и macOS**: без переписывания ядра, только UI-адаптация и платформенные адаптеры.
