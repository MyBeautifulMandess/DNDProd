# 06 — Сетевая модель: лобби и синхронизация

На старте — **локальная сеть**. Интернет-подключение (через сервер на устройстве мастера с пробросом портов или ретранслятор) — фаза позднее (см. `07-roadmap.md`).

## 1. Топология

- **Сервер** поднимается на устройстве мастера при запуске комнаты.
- **Клиенты** — устройства игроков в той же Wi-Fi/LAN-сети.
- Обнаружение: мастер показывает IP:порт и QR-код; опционально — UDP-broadcast для авто-поиска комнат в сети.

## 2. Транспорт

- **WebSocket** как основной канал (дуплекс, низкая задержка).
- Порт по умолчанию: 7777 (TCP). Настраивается.
- Протокол: JSON-сообщения с полем `type` и `payload`. Версия протокола в каждом сообщении (`v`).

## 3. Сообщения (минимальный набор)

| type | Направление | Назначение |
|---|---|---|
| `hello` | клиент→сервер | представление: имя игрока, id персонажа |
| `welcome` | сервер→клиент | подтверждение, снапшот комнаты, права |
| `state` | сервер→клиенты | полный снапшот состояния (карта, токены, туман) |
| `token_move` | клиент→сервер / сервер→все | перемещение пешки (id, x, y); сервер валидирует права и размер пешки |
| `token_remove`, `token_resize` | мастер→сервер→все | удаление пешки и смена её размера 1–4 клеток (только мастер) |
| `fog_update` | сервер→клиенты | изменение тумана войны (мастер) |
| `map_switch` | сервер→клиенты | смена активной карты |
| `chat` | обе стороны | сообщение: текст или бросок |
| `roll` | клиент→сервер / сервер→все | бросок кубиков; флаг `hidden` — только мастеру |
| `hp_update` | клиент→сервер / сервер→все | изменение хитов персонажа/токена |
| `image_show` | сервер→клиенты | картинка на экран игроков (URL `/image.png?v=N`) |
| `image_hide` | сервер→клиенты | убрать картинку с экрана игроков |
| `character_snapshot` | клиент→сервер→мастер | снимок персонажа при подключении (`hello`), уходит только мастеру в архив |
| `draw` | обе стороны | штрихи рисования на поле |
| `ping` / `pong` | обе | keep-alive |

## 4. Состояние комнаты (авторитет — сервер)

```json
{
  "protocol": 1,
  "room": { "adventure_id": "...", "map_key": "...", "map_id": "...", "started_at": 0 },
  "map": { "grid": { "cell_px": 70, "cols": 30, "rows": 20 } },
  "tokens": [ { "id": "t1", "kind": "player|monster|npc", "owner": "player_id|null", "x": 3, "y": 5, "hp": 12, "max_hp": 20, "visible": true } ],
  "fog": { "revealed": [[x, y], "..."], "grid": true },
  "players": [ { "id": "p1", "name": "...", "character_id": "...", "rights": { "move_own": true } } ],
  "log": [ ]
}
```

- Сервер хранит состояние в памяти; персистентность — только в приключении (для возобновления).
- Рассинхрон: клиент, получив `state`, заменяет локальное состояние целиком.

## 5. Безопасность и права

- Игрок может отправлять `token_move` только для токена с `owner == свой id` (или если мастер дал право).
- Скрытые броски: сервер не рассылает их другим игрокам.
- Локальная сеть: без авторизации на старте; для интернета — обязательный пароль комнаты (см. roadmap).

## 6. Интернет-режим (будущее)

- Вариант А: проброс портов на роутере мастера (без изменения кода).
- Вариант Б: облачный ретранслятор (WebSocket/TURN), требует учётных записей.
- В любом случае протокол тот же; меняется только транспорт подключения.

## 7. Тестирование

- Юнит-тесты валидации прав (кто может двигать какой токен).
- Интеграционный тест: 1 сервер + 2 клиента на localhost, сценарий «ход сессии» из `04/05` документов.

## 8. Реализация (2026-11-19, фаза 3)

- **Транспорт** (слой `platform/network/`): `ShelfLobbyServer` (`shelf_web_socket`, `dart:io`) и `ChannelLobbyClient` (`web_socket_channel`). Оба реализуют интерфейсы из `lobby_transport.dart`; `preferredLocalIp()` отдаёт IP в сети без привязки к Windows.
- **Протокол** (`lobby/protocol/`): `decodeLobbyMessage()` отклоняет сообщения с чужим `v`, неизвестным `type` и не-объектным `payload`. Добавлен тип `error` для ошибок валидации и разрыва соединения. Формула броска разбирается строго (`2к6+3`, `1d20-1`), вычисление — через `core/rules/dice.dart` на сервере.
- **Сервер как мастер**: отдельный DM-сокет не нужен — мастер управляет состояние локально (`submit`/методы `moveToken`, `addToken`, `setFog` и т.д.), все клиенты — игроки. Локальный поток `messages` содержит и события игроков, и скрытые броски.
- **Скрытые броски**: сервер считает результат и отправляет `roll` с `hidden: true` только мастеру; остальным — системная запись «<имя>: скрытый бросок» без результата.
- **Права**: `token_move` проверяется через `canMoveToken()`; `hp_update`, `fog_update`, `map_switch`, `image_show` доступны только мастеру; `draw` — всем. Разрешение игрокам двигать свои пешки переключается мастером и рассылается в `state`.
- **Снапшот** (`core/models/room.dart`): `RoomState.toJson/fromJson` — `room`, `map.grid`, `tokens`, `fog.revealed`, `players` с правами. Клиент получает `welcome` со своим `player_id` и полным снапшотом, затем заменяет состояние каждым `state`.
- **QR**: мастер показывает `ws://<IP>:<порт>/ws` текстом и QR-кодом (`qr_flutter`); игрок вводит `IP:порт` вручную. Сканер камеры, UDP-обнаружение, пароль и персистентность комнаты не реализованы (интернет-режим — фаза 6, приключения — фаза 5).
- **Тесты**: `test/lobby_protocol_test.dart` (кодек, формулы, JSON снапшота), `test/lobby_server_test.dart` (1 сервер + 2 клиента: welcome, права, чат, скрытый бросок, отключение), `test/lobby_flow_test.dart` (controllers end-to-end), `test/lobby_ui_test.dart` (экраны).
- **Фон карты** (2026-11-19, шаг 4.1): тот же HTTP-сервер по `shelf.Cascade` раздаёт `GET /map.png` (байты импортированной мастером карты, `Cache-Control: no-store`), WebSocket по-прежнему на `/ws`. В `state.map_id` лежит либо `asset:assets/maps/grid_basic.jpg`, либо URL `http://<адрес>:<порт>/map.png?v=N` (версия меняется при смене карты, чтобы клиент не показывал старый кэш). Клиент выбирает `AssetImage`/`NetworkImage` по префиксу. Карта живёт в памяти сервера до остановки комнаты.
- **Штрихи и пешки** (2026-11-19, шаг 4.2): снапшот дополнен `tokens[].size` (1–4) и `draw.strokes` (клетки, автор, цвет). `draw` теперь не просто ретранслируется: сервер проверяет клетки, назначает цвет по автору, хранит до 200 последних штрихов и рассылает новый снапшот, поэтому подключившийся позже игрок видит рисунки. `token_remove`/`token_resize` доступны только мастеру; перемещение пешки учитывает её размер при проверке границ поля.
- **Мультикарты и картинки** (2026-11-19, шаг 5.2): `ShelfLobbyServer` принимает `List<LobbyMap>` и `initialMapKey`, хранит снапшот каждой карты; `room.map_key` в JSON и `map_switch` с полем `map_key` позволяют клиенту восстановить нужное состояние. При переключении текущая карта сохраняется, а пешки подключившихся игроков добавляются в целевую, если их там нет. Импорт фона посреди сессии обновляет снапшот активной карты. `collectMapStates()` возвращает все состояния для переноса в приключение; пешки `TokenKind.player` при переносе отбрасываются.
- **HTTP и версия протокола** (2026-11-19, шаг 5.2): тот же сервер отдаёт `GET /image.png?v=N` (байты картинки для игроков, `Cache-Control: no-store`, смена версии при показе новой); `image_hide` убирает оверлей. Протокол остаётся v1: `image_hide`, `character_snapshot` и `room.map_key` добавлены без migrations — старые клиенты игнорируют неизвестные типы и лишнее поле. `character_snapshot` приходит от игрока вместе с `hello` и виден только мастеру (автоархив персонажей).
